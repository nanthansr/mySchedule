02 AIOps Tools — What to Know, What to Demo
Two distinct stacks exist: AIOps (AI for IT operations — reducing alert noise, incident correlation) and MLOps observability (monitoring ML model health in production). You need literacy in both. You don't need to use all of them — but you need to be able to talk intelligently about the landscape and demo the open-source equivalents.
Prometheus + Grafana
Open Source · MLOps + AIOps
You already have this. The foundation of self-hosted observability for both infra and ML models. Prometheus scrapes metrics; Grafana visualizes them. Adding anomaly detection logic directly in your Grafana dashboards (via alerting rules) is the open-source equivalent of enterprise AIOps.
Interview move: Frame your Prometheus/Grafana setup as "self-managed AIOps pipeline" — that's the honest comparison.
DEMO THIS
Datadog
Commercial · Most mentioned in JDs
The enterprise standard. Full-stack observability — infra, APM, logs, security, ML model monitoring. Its "Bits AI" feature now does autonomous triage: fires alerts, gathers telemetry, reads runbooks, and proposes root causes before an engineer checks in. You'll encounter this in any mid-to-large company.
Interview move: "I use Prometheus/Grafana; Datadog is the managed equivalent at scale. Same primitives — metrics, logs, traces — plus AI-powered correlation."
KNOW IT
MLflow
Open Source · MLOps core
Already in your stack for experiment tracking. The model registry is what transforms it from a tracking tool into a production MLOps component. Model versioning, stage transitions (Staging → Production), artifact storage — this is what Stage 3 of your pipeline should demonstrate.
Interview move: "We use MLflow for full model lifecycle — tracking, registry, deployment artifacts. Same workflow as SageMaker Model Registry, just self-hosted."
DEMO THIS
Evidently AI / WhyLabs
Open Source · MLOps drift monitoring
Purpose-built for ML model monitoring: data drift, prediction drift, feature distribution shift. Evidently generates HTML reports or exports metrics to Prometheus. This is the tool that legitimizes your anomaly detection layer — instead of custom numpy code, you'd use Evidently to detect when the fraud model's input distribution shifts.
Interview move: A one-weekend integration. Adds credibility to your monitoring story significantly.
HIGH VALUE ADD
New Relic
Commercial · Observability + AIOps
Strong APM with "Applied Intelligence" for anomaly detection and alert correlation. Its free tier is actually generous — useful for personal demos. "New Relic AI" (GenAI layer) lets engineers query data in plain English. Appears in ~30% of JDs, more in fintech and SaaS companies.
Interview move: Awareness-level. Mention it when discussing commercial observability options.
BE AWARE
Moogsoft / BigPanda / PagerDuty
Commercial · Enterprise AIOps
Alert noise reduction and incident correlation at enterprise scale. Moogsoft uses ML to cluster related alerts into incidents and suggest root causes. PagerDuty adds automated on-call routing and runbook execution. You'll encounter these at companies running complex distributed systems — not typically in portfolio projects.
Interview move: Know the problem they solve (alert fatigue, MTTR reduction). You don't need to demo them — just speak the language.
LANGUAGE ONLY
Dynatrace
Commercial · Enterprise AI observability
The most sophisticated causal AI engine in enterprise observability. Its "Davis AI" does deterministic root-cause analysis across full distributed traces. Dominant in large enterprises and regulated industries (banking, insurance). Heavy in Canadian enterprise JDs that ask for observability architecture experience.
Interview move: "Dynatrace's Davis AI is the enterprise version of what I built manually — automated root cause correlation across infra + ML model metrics."
LANGUAGE ONLY

05 How to Talk About Your Project in Interviews
When asked about observability "I built a self-managed AIOps layer using Prometheus and Grafana — scraping both infra metrics and model-level fraud rate stats. The anomaly detection component triggers when prediction distributions drift from the training baseline. Enterprise equivalent would be Datadog or Dynatrace, same primitives."
When asked about CI/CD for ML "Our pipeline does test → model retrain → Docker build → image push. The deliberate architectural choice was to retrain in CI as an intermediate step, then move to a decoupled pattern in Stage 3 where model artifacts live in a registry and get fetched at deploy time."
When asked about class imbalance "Fraud detection is inherently imbalanced — we had ~0.17% fraud rate in the dataset. I used scale_pos_weight in XGBoost to weight the positive class. Evaluated with AUC-PR, not accuracy — accuracy is misleading when negatives are 99.8% of the data."
When asked about model governance "MLflow handles experiment tracking and artifact versioning. The model registry pattern I'm implementing in Stage 3 enforces explicit stage gates — nothing moves to production without a registered version. Audit trail is automatic."
When asked about AI-native engineering "I use Claude/Copilot to draft infrastructure configs and then harden them manually — review every line, understand what changed. The AI generates, I own. That's the 2026 workflow — not AI replacing judgment, AI removing boilerplate so judgment is all that's left."
